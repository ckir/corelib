corelib

User Guide · version 0.4.0 · 2026-10-16

A multi-runtime TypeScript toolkit: resilient HTTP, logging, configuration and databases (@ckirg/corelib), Nasdaq market data and streaming (@ckirg/corelib-markets), and an edge proxy service (@ckirg/corelib-cloud).

Example convention: a heading tagged ran locally was executed against the repository's built packages (using local stub servers and scratch files; the output shown is real, with timestamps, ports and ANSI colours trimmed). A heading tagged illustrative needs credentials, a paid or public network service, or a deployment, so it was not run and its output is omitted or marked illustrative.

1. Overview

corelib is a pnpm monorepo that publishes three npm packages for Node.js (24+), Bun and Deno, plus a Rust native addon that the TypeScript packages load over N-API.

PackageUse it for
@ckirg/corelibResilient HTTP (endPoint, endPoints, RequestProxied), structured logger, ConfigManager, SQLite/PostgreSQL createDatabase, runtime helpers, cron include/exclude, native Core.
@ckirg/corelib-marketsNasdaq market status and monitor, symbol directory (MarketSymbols), CNN Fear and Greed, Yahoo historical data, Nasdaq 100 list, real-time Alpaca / Finnhub / Yahoo streaming.
@ckirg/corelib-cloudA Hono application (createRouter) that exposes the above as an authenticated HTTP service on Cloudflare Workers, AWS Lambda or Cloud Run.

This guide is for application developers who consume these packages. It does not cover contributing to the repository.

Smallest useful program ran locally

// hello.mjs
import { detectRuntime, getMode, getPlatform, sleep, Core } from '@ckirg/corelib';

console.log(detectRuntime(), getMode(), getPlatform());
const t = Date.now();
await sleep(100);
console.log('slept at least 95 ms:', Date.now() - t >= 95);
console.log('native addon loaded:', Core.isFfiAvailable());
node development linux

Native binary caveats illustrative

  • Bun blocks dependency postinstall scripts. Add "trustedDependencies": ["@ckirg/corelib"] to your package.json.
  • The postinstall skips the download when MODE=development or under GitHub Actions. Do not put MODE=development in a consuming app's .env.
  • Fetch it manually if it was skipped: node node_modules/@ckirg/corelib/scripts/postinstall.js
  • If the binary is missing the library still loads; only the native features (Core, streaming) are disabled. Check Core.isFfiAvailable().
The per-package READMEs still say the packages are "Not on the public npm registry" and (ts-core, ts-markets) show a v0.1.17 tarball URL. The root README and the current release (0.4.0) say they are on npm. See section 15.

3. Quick start

First resilient request, with a result you can branch on ran locally

A throw-away local server stands in for a real API so the example is self-contained. Replace the URL with your own.

// quick.mjs
import http from 'node:http';
import { endPoint } from '@ckirg/corelib';

const srv = http.createServer((req, res) => {
  res.setHeader('content-type', 'application/json');
  res.end(JSON.stringify({ symbol: 'AAPL', price: 189.5 }));
}).listen(0, async () => {
  const result = await endPoint(`http://127.0.0.1:${srv.address().port}/quote/AAPL`);
  if (result.status === 'success') {
    console.log(result.value.status, result.value.body);
  } else {
    console.error('failed:', result.reason);
  }
  srv.close();
});
200 { symbol: 'AAPL', price: 189.5 }

That is the whole pattern: nothing throws, every call returns { status: 'success', value } or { status: 'error', reason }.

4. Core concepts

  • Result unions instead of exceptions. HTTP calls return RequestResult (value is a SerializedResponse with ok, status, statusText, headers, url, redirected, type, body and a cid correlation id). Database calls return DatabaseResult. Market calls return similar unions. Always branch on status.
  • Layered configuration. Priority is CLI flags > CORELIB_* environment variables > config file > built-in defaults (section 7).
  • Runtime detection. The logger and several helpers choose an implementation for node, bun, deno, cloudflare, aws-lambda or gcp-cloudrun. Set RUNTIME= to force it.
  • Native core. Streaming engines and a few helpers run in Rust. They degrade gracefully when the binary is absent.

5. HTTP requests

Retries use full-jitter backoff. GET, HEAD and OPTIONS are retried on network errors, 5xx and up to five 429 responses; other 4xx responses are not retried. Defaults: 50 s timeout, 5 retries, 3 s backoff cap. The examples below run against a small local stub server (full code in the recipe in section 13); base is its URL.

5.1 endPoint and endPoints

Successful GET ran locally

const ok = await endPoint(`${base}/quote/AAPL`);
console.log(ok.status, ok.value.status, ok.value.body, ok.cid);
success 200 { symbol: 'AAPL', price: 189.5 } 1

HTTP error: a value, not an exception ran locally

const nf = await endPoint(`${base}/nope`);
console.log(nf.status, nf.reason.status, nf.reason.statusText);
error 404 Not Found
On an error result the response body is the literal string "[Body already consumed]", so the server's error payload is not available through reason.body (observed on 0.4.0; see section 15). A warning is also logged.

Retries on 5xx, with tuned retry options ran locally

The server answers 503 twice, then 200. Options are passed to ky.

const fl = await endPoint(`${base}/flaky`, { retry: { limit: 4, backoffLimit: 200 } });
console.log(fl.status, fl.value.body, 'server hits:', hits);
success { ok: true } server hits: 3

POST with JSON and an auth header ran locally

const post = await endPoint(`${base}/echo`, {
  method: 'POST',
  json: { a: 1 },
  headers: { Authorization: 'Bearer YOUR_TOKEN' },
});
console.log(post.value.body);

// A pre-serialised string body gets content-type: application/json automatically
const post2 = await endPoint(`${base}/echo`, { method: 'POST', body: JSON.stringify({ b: 2 }) });
console.log(post2.value.body);
{
  method: 'POST',
  body: '{"a":1}',
  ct: 'application/json',
  auth: 'Bearer YOUR_TOKEN'
}
{ method: 'POST', body: '{"b":2}', ct: 'application/json' }

Only GET, HEAD and OPTIONS are retried by default, so a POST that fails is not replayed.

Several URLs in parallel; network failures ran locally

const many = await endPoints([`${base}/quote/AAPL`, `${base}/nope`]);
console.log(many.map(r => r.status + ':' + (r.status === 'success' ? r.value.status : r.reason.status)));

// Connection refused (nothing listening): reason is a serialised Error
const dead = await endPoint(`http://127.0.0.1:${closedPort}/`, { retry: { limit: 0 } });
console.log(dead.status, dead.reason.name);
[ 'success:200', 'error:404' ]
error NetworkError

Results come back in input order. Config keys retrieve.timeout, retrieve.retry.limit and retrieve.retry.backoffLimit change the defaults globally (timeout is clamped to 1 000..120 000 ms, retry limit to 0..10, backoff to 0..60 000 ms); options you pass per call win over config.

If you call endPoint before ConfigManager.initialize() resolves, a one-time warning is logged (ConfigManager.get("retrieve.timeout") called before initialize() resolved) and the seeded defaults are used. Call await ConfigManager.getInstance().initialize() at start-up to avoid it (it is suppressed when NODE_ENV=production).

5.2 RequestProxied

new RequestProxied(proxyBaseUrls) sends each request to a proxy as <proxy>/?url=<target> (the proxy is expected to behave like the ts-cloud GET /api/v1/ky?url= route). Single requests rotate round-robin and fall back to every other proxy before failing; endPoints spreads the batch across proxies. Signature: endPoint(url, suffix = "", options = {}).

Rotation and a path suffix ran locally

Two local stub proxies answer with their own name (via), the path they received and the url query parameter. The suffix call lands on proxy-b because the round-robin pointer was on its turn.

const client = new RequestProxied([proxyA, proxyB]);
for (let i = 0; i < 3; i++) {
  const r = await client.endPoint('https://api.example.com/quote/AAPL');
  console.log(r.status, r.value.body.via);
}
const many = await client.endPoints(['https://t1.example.com', 'https://t2.example.com']);
console.log(many.map(r => r.value.body.via));

// Append a path to the proxy base, and pass ky options as the third argument
const s = await client.endPoint('https://api.example.com/q', '/fetch', { headers: { 'x-trace': '1' } });
console.log(s.value.body);
success proxy-a
success proxy-b
success proxy-a
[ 'proxy-a', 'proxy-b' ]
{ via: 'proxy-b', path: '/fetch', target: 'https://api.example.com/q' }

Fallback when a proxy returns 502 ran locally

const mixed = new RequestProxied([badProxy502, goodProxy]);
// Argument order is (url, suffix, options): pass '' as the suffix when you only want options
const m = await mixed.endPoint('https://api.example.com/x', '', { retry: { limit: 0 } });
console.log(m.status, m.value.body.via);
success good
Argument order is endPoint(url, suffix, options), unlike endPoint(url, options) of the standalone function. Passing the options object second puts it in the suffix slot (observed: it was stringified into the request path as /[object Object]).

Only network errors and proxy-originated 502/503/504 count against a proxy's health; a 404 from the target does not. After 3 consecutive failures a proxy is removed for the lifetime of the instance.

Validation errors ran locally

try { new RequestProxied([]); } catch (e) { console.log(e.message); }
try { new RequestProxied(['nope']); } catch (e) { console.log(e.message); }
const bad = await client.endPoint('https://api.example.com/q', 'https://evil.example.org/');
console.log(bad.status, bad.reason.message);   // a suffix may not leave the proxy host
RequestProxied: at least one proxy URL is required
RequestProxied: invalid proxy URL "nope"
error Invalid proxy suffix

6. Logging

logger has a strict signature (msg: string, extras?: object) with levels trace, debug, info, warn, error, fatal, plus child(bindings), setTelemetry('on'|'off'), level, flush(). It is built on pino and picks an implementation per runtime.

Env varDefaultMeaning
LOG_LEVELinfoMinimum level (Node implementation).

Telemetry on a record ran locally

logger.setTelemetry('on');
log.warn('with telemetry', { telemetry: true });

With telemetry on and { telemetry: true } in the extras, the record gains a telemetry object (runtime, os, arch, pid, ppid, cwd, uptime, osVersion, loadAvg, memory, ...) from getSysInfo(), cached for 5 seconds (the full output, not shown here, is long).

The telemetry object includes an env map of your whole process environment. Values are redacted only for variable names that look secret (for example tokens, keys, passwords). Other values, such as PATH, HOME and URLs like CORELIB_TURSO_URL, appear verbatim. Leave telemetry off, or do not ship these records to a third party, unless that is acceptable (observed on 0.4.0).

7. Configuration with ConfigManager

ConfigManager is a singleton EventEmitter. get(path) (instance or static form) is synchronous, uses dot notation and returns undefined for a missing key. Bundled defaults are seeded at construction, so reads are safe before initialize(), but gate long-lived components on whenReady().

Priority, highest first: CLI flags (--a-b-c value or --a-b-c=value), environment (CORELIB_A_B_C), config file (-C file / --config file), bundled defaults. Values are parsed: true/false, numbers, and JSON arrays/objects.

Initialise, read, update, subscribe ran locally

import { ConfigManager } from '@ckirg/corelib';
const config = ConfigManager.getInstance();
await config.initialize();     // concurrent calls share one run
console.log(config.isInitialized, config.get('retrieve.timeout'), config.get('retrieve.retry.limit'));
console.log(ConfigManager.get('database.port'));      // not a default key

config.on('change:database.port', (p) => console.log('port changed to', p));
config.updateValue('database.port', 6000);
console.log(ConfigManager.get('database.port'));
true 50000 5
undefined
port changed to 6000
6000

updateValue also emits a generic change event { path, value }; initialize() emits initialized. Other methods: getConfig(), toJsonString(), toBuffer(), whenReady(), loadExternalConfig(source).

Command-line overrides ran locally

// c2.mjs prints retrieve, database.port and feature.flags after initialize()
$ node c2.mjs --retrieve-retry-limit 2 --database-port=7000 --feature-flags '["a","b"]'
{"timeout":50000,"retry":{"limit":2,"backoffLimit":3000}} 7000 [ 'a', 'b' ]

Environment overrides ran locally

$ CORELIB_RETRIEVE_RETRY_LIMIT=3 CORELIB_RETRIEVE_TIMEOUT=1500 node c2.mjs
{"timeout":1500,"retry":{"limit":3,"backoffLimit":3000}} undefined undefined
Env names map to lower-case keys with _ as the separator, so camelCase keys cannot be set that way. CORELIB_RETRIEVE_RETRY_BACKOFFLIMIT=100 produced a stray key: {"limit":5,"backoffLimit":3000,"backofflimit":100}. Use the CLI form for those: --retrieve-retry-backoffLimit=100 gave {"limit":5,"backoffLimit":100}.

Layered config file (YAML, TOML, JSON, JSON5, JSONC, INI) ran locally

A file is layered as commonAll, then your app's section (common, then <linux|windows>.<development|production>). The app name is the folder name of the nearest workspace root (a directory with pnpm-workspace.yaml or a package.json with workspaces), else the current directory's name; the match is case-insensitive. Here the working directory is called app2.

# settings.yaml

  retrieve:
    timeout: 20000

  common:
    greeting: hello
  linux:
    development:
      database:
        port: 5433
    production:
      database:
        port: 5432

A .enc file is decrypted first; an http(s):// source is fetched with endPoint. Remote and encrypted loading was not run here.

Error case: config file not found ran locally

Do not cache a sub-section at module scope (const db = ConfigManager.get('database')): a later override can be missed. Read ConfigManager.get('database.port') where you use it.

8. Databases

createDatabase(config) returns a Database with query(sql, params?), transaction(callback) and disconnect(). dialect is 'sqlite' (LibSQL: local file: URLs or Turso libsql://) or 'postgres'. Params are a positional array (?) or an object (:name). Config also accepts mode ('stateless' | 'stateful'), timeoutMs, logger, paramRedactor, getTraceId; SQLite adds authToken, journalMode, synchronous, maxConnections.

Create, insert, select ran locally

import { createDatabase } from '@ckirg/corelib';
const db = await createDatabase({ dialect: 'sqlite', url: 'file:./app.db', mode: 'stateful' });

await db.query('CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT, active INTEGER)');
console.log(JSON.stringify(await db.query('INSERT INTO users (name, active) VALUES (?, ?)', ['ada', 1])));
await db.query('INSERT INTO users (name, active) VALUES (:n, :a)', { n: 'grace', a: 0 });   // named params
console.log(JSON.stringify(await db.query('SELECT * FROM users WHERE active = ?', [1])));
{"status":"success","value":{"rows":[],"affectedRows":1,"lastInsertId":"1"}}
{"status":"success","value":{"rows":[{"id":1,"name":"ada","active":1}],"affectedRows":0}}

Transactions: commit and roll back ran locally

Return { status: 'success', value } from the callback to commit, or an error result to roll back.

const tx = await db.transaction(async () => {
  await db.query('INSERT INTO users (name, active) VALUES (?, 1)', ['linus']);
  return { status: 'success', value: 'committed' };
});
const tx2 = await db.transaction(async () => {
  await db.query('INSERT INTO users (name, active) VALUES (?, 1)', ['rolled-back']);
  return { status: 'error', reason: { message: 'abort' } };
});
console.log(JSON.stringify(tx), JSON.stringify(tx2));
console.log(JSON.stringify((await db.query('SELECT count(*) AS n FROM users')).value.rows));
{"status":"success","value":"committed"} {"status":"error","reason":{"message":"abort"}}
[{"n":3}]

Cron include/exclude

includeExcludeCron(includeExprs, excludeExprs, handler, timezone?, onError?) returns a croner job that ticks every second and runs handler when any include expression matches and no exclude does. Expressions may have 5, 6 (with seconds) or 7 fields and are validated up front. A throwing or rejecting handler goes to onError (or the logger) and does not stop the job.

Run every second except even seconds ran locally

const job = includeExcludeCron(['* * * * * *'], ['*/2 * * * * *'], () => {
  console.log('tick, second is odd:', new Date().getSeconds() % 2 === 1);
}, 'UTC');
await sleep(4200);
job.stop();
tick, second is odd: true
tick, second is odd: true

Invalid expression fails fast ran locally

try { includeExcludeCron(['bad cron'], [], () => {}); } catch (e) { console.log(e.message); }

10. Market data (corelib-markets)

Most calls here reach live services (Nasdaq, CNN, Yahoo, brokers). Examples that hit them are marked illustrative. Where possible, the local examples redirect the package to a stub server by overriding config keys with ConfigManager.updateValue.

10.1 Market status and sleep calculation

MarketStatus.getStatus() reads markets.nasdaq.statusEndpoint and returns NasdaqResult<NasdaqMarketInfo>. getSleepDuration(info) returns milliseconds until the next pre-market or open (0 when open; 300 000 if the next trade date cannot be parsed).

Sleep until the next event ran locally

The system clock is faked to 03:00 New York time on 9 Mar 2026 (07:00 UTC, EDT); the info object is trimmed to the fields that matter.

const info = { mrktStatus: 'Closed', nextTradeDate: 'Mar 10, 2026', pmOpenRaw: '2026-03-09T04:00:00',
               openRaw: '2026-03-09T09:30:00', closeRaw: '2026-03-09T16:00:00', ahCloseRaw: '2026-03-09T20:00:00',
               /* ...remaining NasdaqMarketInfo fields... */ };
Date.now = () => new Date('2026-03-09T07:00:00Z').getTime();
console.log(MarketStatus.getSleepDuration(info));                          // 1 hour
console.log(MarketStatus.getSleepDuration({ ...info, mrktStatus: 'Open' })); // already open
3600000
0

Fetch status and monitor phase changes against a stub ran locally

cfg.updateValue('markets.nasdaq.statusEndpoint', `http://127.0.0.1:${port}/api/market-info`);
const st = await MarketStatus.getStatus();
console.log(st.status, st.value.mrktStatus);

const monitor = new MarketMonitor({ liveIntervalSec: 15, closedIntervalSec: 1800 });
monitor.on('status-change', (phase, data, heuristic) => {
  console.log('phase', phase, 'heuristic', !!heuristic, data.nextTradeDate);
  monitor.stop();
});
monitor.on('stopped', () => console.log('stopped; running =', monitor.isRunningState));
monitor.start();
success Closed
phase closed heuristic false Mar 10, 2026
stopped; running = false

MarketMonitor options: liveIntervalSec, closedIntervalSec, warnIntervalSec, proxies (proxies are called at <proxy>/api/v1/markets/nasdaq/status, i.e. a ts-cloud service). Phases: "open" | "pre-market" | "after-hours" | "closed". It emits status-change after the first successful poll and on each change, falls back to a time-based heuristic during fetch failures (heuristic = true), and emits stopped. Properties: isRunningState, currentPhase.

Against the real Nasdaq API illustrative

const result = await MarketStatus.getStatus();
if (result.status === 'success') {
  console.log(`Nasdaq Status: ${result.value.mrktStatus}`);
  console.log(`Sleeping ${MarketStatus.getSleepDuration(result.value)} ms`);
}

10.2 MarketSymbols (symbol directory)

new MarketSymbols(db?, ingestors?). get(symbol) returns a MarketSymbolRow (symbol, name, type 'rt'|'eod', class, ts, active) or null; refresh() forces a reload; close() releases the store. The backend is the constructor argument (a path means SQLite, mongodb:// or mongodb+srv:// means MongoDB, { dbUrl, dbToken } means Turso) or markets.nasdaq.symbols.store (sqlite default, turso, mongodb). On Node it searches store, then Nasdaq API, then ingestors; on edge runtimes API first.

Load the directory from stub files and look up symbols ran locally

The refresh normally downloads two files from Nasdaq's FTP/HTTPS directory. Here the two URL keys point at a local server serving files in the same format, and minRows (default 1000; a guard against truncated downloads) is lowered for the demo.

cfg.updateValue('markets.nasdaq.symbols.nasdaqListedUrl', `${base}/nasdaqlisted.txt`);
cfg.updateValue('markets.nasdaq.symbols.otherListedUrl',  `${base}/otherlisted.txt`);
cfg.updateValue('markets.nasdaq.symbols.minRows', 2);
const symbols = new MarketSymbols('./symbols-demo.sqlite');
for (const s of ['AAPL', 'IBM', 'QQQ']) console.log(JSON.stringify(await symbols.get(s)));

10.4 Real-time streaming

AlpacaStreaming, FinnhubStreaming and YahooStreaming are EventEmitters backed by the Rust WebSocket engine. Construct (synchronous, wrap in try/catch), await init(config), await start(), subscribe([...]). Events: pricing, log, connected, disconnected, reconnecting, error; Alpaca and Yahoo also emit market and silence-reconnect.

Alpaca, Finnhub and Yahoo illustrative

import { AlpacaStreaming, FinnhubStreaming, YahooStreaming } from '@ckirg/corelib-markets';

// Alpaca: credentials via init() or APCA_API_KEY_ID / APCA_API_SECRET_KEY
const alpaca = new AlpacaStreaming();
await alpaca.init({ keyId: 'YOUR_KEY', secretKey: 'YOUR_SECRET', silenceSeconds: 60 });
await alpaca.start();
alpaca.subscribe(['AAPL', 'TSLA']);                       // or { trades?, quotes?, bars? }
alpaca.on('pricing', (d) => console.log(`${d.symbol}: $${d.price}`));
alpaca.on('error', (e) => console.error('error', e));

// Finnhub: token via init() or FINNHUB_API_KEY; payload fields are camelCase
const finnhub = new FinnhubStreaming();
await finnhub.init({ token: 'YOUR_FINNHUB_API_KEY' });
await finnhub.start();
await finnhub.subscribe(['MSFT']);
finnhub.on('pricing', (d) => console.log(d.messageType, d.symbol, d.price, d.timestamp));

// Yahoo: no credentials; the ticker field is `id`, not `symbol`
const yahoo = new YahooStreaming();
await yahoo.init({ silenceSeconds: 45 });
await yahoo.start();
yahoo.subscribe(['AAPL', 'BTC-USD']);
yahoo.on('pricing', (d) => console.log(`${d.id}: $${d.price}`));

alpaca.stop(); yahoo.stop(); await finnhub.stop();
Connecting needs credentials or a live feed, so start() and live data are not run here. Measured locally: await new AlpacaStreaming().init({}) with no credentials resolves in a few milliseconds (it opens the persistence database and does not connect). However, a Node process that has constructed any AlpacaStreaming does not exit on its own, even after init() and stop() (killed by a 20 s timeout in each test); end such scripts with process.exit(). Supply credentials (or the environment variables) before calling start(). Use stream.clean() to wipe the persistence database (dbPath, default under the temp dir).

A self-contained HTTP test harness ran locally

This is the stub server used by the section 5 examples. It serves a JSON quote, a flaky endpoint (two 503s then 200), an echo endpoint and a 404.

// stub.mjs
import http from 'node:http';
import { endPoint } from '@ckirg/corelib';

let hits = 0;
const srv = http.createServer((req, res) => {
  const u = new URL(req.url, 'http://x');
  res.setHeader('content-type', 'application/json');
  if (u.pathname === '/quote/AAPL') return res.end(JSON.stringify({ symbol: 'AAPL', price: 189.5 }));
  if (u.pathname === '/flaky') {
    if (++hits < 3) { res.statusCode = 503; return res.end('busy'); }
    return res.end('{"ok":true}');
  }
  if (u.pathname === '/echo') {
    let b = ''; req.on('data', (c) => (b += c));
    return req.on('end', () => res.end(JSON.stringify({ method: req.method, body: b,
      ct: req.headers['content-type'], auth: req.headers.authorization })));
  }
  res.statusCode = 404; res.end('{"error":"not found"}');
}).listen(0, async () => {
  const base = `http://127.0.0.1:${srv.address().port}`;
  console.log((await endPoint(`${base}/flaky`, { retry: { limit: 4, backoffLimit: 200 } })).value.body, 'hits', hits);
  srv.close();
});
{ ok: true } hits 3

15. Where the docs and the code disagree

These were found while verifying the examples. The guide follows the code's behaviour where it could be observed.

  1. Install instructions. The ts-core, ts-markets and ts-cloud READMEs say "Not on the public npm registry" (ts-core and ts-markets show a v0.1.17 GitHub tarball install); the root README says they are on the public npm registry (version 0.4.0 in all manifests). npm view @ckirg/corelib version returns 0.4.0, so the root README is right and the package READMEs are out of date.
  2. Tool versions. The root README shows a TypeScript 5.0+ badge while the catalog pins TypeScript ^6.0.3.
  3. RequestProxied pruning. The ts-core README says unhealthy proxies are pruned "on first failure"; the code (and its doc comment) removes a proxy after 3 consecutive failures.
  4. Database config type. The ts-core README example createDatabase({ dialect: 'sqlite', url }) omits mode, which BaseDbConfig declares as required ('stateless' | 'stateful'). It runs at runtime without it, but TypeScript users get a type error.
  5. RequestUnlimited. READMEs describe a RequestUnlimited class; the package exports the functions endPoint and endPoints (plus RequestProxied), not a class of that name.
  6. Native addon version. Core.getVersion() returned 0.2.0 from the bundled ts-core/corelib-rust.node while the package is 0.4.0.
  7. Error bodies. Failed HTTP results carry body: "[Body already consumed]", so the server's error payload is not retrievable from reason.body.
  8. Streaming client keeps the process alive. AlpacaStreaming.init({}) with no credentials resolves in milliseconds, but a process that merely constructs an AlpacaStreaming never exits naturally, even after init() and stop() (measured on Node: still running when a 20 s timeout killed it). The earlier suspicion that init hangs was wrong; the hang is the process not exiting. Cause not investigated.
