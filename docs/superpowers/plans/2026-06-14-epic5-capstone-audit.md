# Epic 5 — Capstone Global Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Audit the complete, instrumented monorepo across 5 clusters; reproduce each suspected weakness with a durable probe; fix **only** the confirmed hard-gate criticals inline; backlog the rest.

**Architecture:** Gated-hybrid audit. Each task authors a probe (reusing the existing `/probes` harness + Epic 4 flight recorder), runs it to get a measurement, records a finding via `probes/tools/scratchpad.mjs`, and — only if it crosses the hard gate (spec §"The gated hard gate") — fixes inline with the probe as the verifying oracle. Heavy probes run on-demand on GitHub Actions (`heavy-probes.yml`, extended), triggered by the controller. Linear phase order: harness → seam/lifecycle → soak → external.

**Tech Stack:** TypeScript (vitest), Rust (`corelib-rust` napi/N-API, crossbeam, tokio, tungstenite), `probes/` standalone harness (vitest + cargo + loom), GitHub Actions `workflow_dispatch`.

**Spec:** `docs/superpowers/specs/2026-06-14-epic5-capstone-audit-design.md`. **Findings register:** `.agent/audit_scratchpad.json` (gitignored) via `probes/tools/scratchpad.mjs`; ranked backlog regenerated by `probes/tools/synthesize.mjs`.

**Audit-task shape (every probe task follows this):**
1. **State-verify** the code under probe (open the real files; if shape differs from this plan, STOP and report `STATE_MISMATCH`).
2. **Author the probe** (reuse harness; new probes live in `probes/js/<id>.probe.test.ts` or `probes/rust/tests/<id>.rs`).
3. **Run it** and capture the measurement (probes print a machine line: `PROBE_CONFIRMED <id> <metric>` when a defect reproduces, else `PROBE_CLEAN <id> <metric>`).
4. **Record the finding:** `node probes/tools/scratchpad.mjs add` with id/severity/cluster/probe-path/outcome.
5. **Gate:** if `PROBE_CONFIRMED` AND it crosses a hard-gate threshold → **fix inline**, re-run the probe to `PROBE_CLEAN`, commit fix+probe together. Else → **commit the probe only** (soft-gate/backlog), leave the fix deferred.

**Verify commands:** local fast gate `pnpm verify:full` + `cd rust && cargo test -- --test-threads=1`. JS probes: `pnpm exec vitest run -c probes/vitest.config.ts probes/js/<id>.probe.test.ts`. Rust probes: `cargo test --manifest-path probes/rust/Cargo.toml <name> -- --nocapture`. Heavy/CI: `gh workflow run heavy-probes.yml -f probe=<id> -f commit=<sha>` → `gh run watch`.

- [ ] **Step 1 — add a parametric generator** alongside the existing flood. Add a second env-gated `#[napi]` export that takes load parameters and a mode, mirroring the existing TSFN shape exactly (`ThreadsafeFunction<String>`, `ThreadsafeFunctionCallMode`). It generates synthetic JSON ticks **in-process from a native thread → TSFN directly (no socket)**, supporting two modes:
```rust
#[napi]
pub fn napi_load_generator(
    rate_per_sec: u32,
    duration_ms: u32,
    bursty: bool, // false = steady; true = recurrent spike→idle→gc-window cycles
    on_event: ThreadsafeFunction<String>,
) -> napi::Result<()> {
    if std::env::var("CORELIB_LOADGEN").unwrap_or_default() != "1" {
        return Ok(()); // production no-op
    }
    std::thread::spawn(move || {
        let deadline = std::time::Instant::now() + std::time::Duration::from_millis(duration_ms as u64);
        let mut seq: u64 = 0;
        while std::time::Instant::now() < deadline {
            if bursty {
                // spike: emit one second's worth fast, then idle 200ms to let the loop drain + GC
                for _ in 0..rate_per_sec { seq += 1; let _ = on_event.call(Ok(synthetic_tick(seq)), ThreadsafeFunctionCallMode::Blocking); }
                std::thread::sleep(std::time::Duration::from_millis(200));
            } else {
                // steady: pace to rate_per_sec
                let per = std::time::Duration::from_micros(1_000_000 / rate_per_sec.max(1) as u64);
                seq += 1; let _ = on_event.call(Ok(synthetic_tick(seq)), ThreadsafeFunctionCallMode::Blocking);
                std::thread::sleep(per);
            }
        }
    });
    Ok(())
}

fn synthetic_tick(seq: u64) -> String {
    // shaped like a real pricing payload but carrying a sequence id for loss/latency accounting
    format!("{{\"seq\":{seq},\"symbol\":\"TEST\",\"price\":1.0,\"ts\":0}}")
}
```

### Task 1.2: Rust-side roundtrip-token latency-sample path

**Files:**
- Create: `rust/src/observability/latency.rs`
- Modify: `rust/src/observability/mod.rs` (add `pub mod latency;`)
- Modify: `diagnostics.rs` or `latency.rs` — the ack entrypoint

- [ ] **Step 0 — state-verify:** `rust/src/observability/mod.rs` declares the Epic-4 modules (`ring_buffer`, `layer`, `napi_dump`). Confirm before adding `latency`.

- [ ] **Step 1 — numeric latency ring + roundtrip token.** Latency is measured **entirely in Rust** (spec §Tooling / agy F-3): when the generator emits tick `seq`, record `Instant` keyed by `seq`; JS acks `seq` back via a `#[napi]` fn; Rust computes `elapsed` against the *same* `Instant` and pushes the micros into a lock-free numeric ring (mirror Epic 4's `crossbeam::ArrayQueue` pattern, but `ArrayQueue<u64>`). NEVER subtract Node's clock from Rust's.
```rust
use crossbeam_queue::ArrayQueue;
use std::collections::HashMap;
use std::sync::{Mutex, OnceLock};
use std::time::Instant;

static SENT: OnceLock<Mutex<HashMap<u64, Instant>>> = OnceLock::new();
static SAMPLES: OnceLock<ArrayQueue<u64>> = OnceLock::new(); // elapsed micros

fn sent() -> &'static Mutex<HashMap<u64, Instant>> { SENT.get_or_init(|| Mutex::new(HashMap::new())) }
fn samples() -> &'static ArrayQueue<u64> { SAMPLES.get_or_init(|| ArrayQueue::new(65536)) }

pub fn mark_sent(seq: u64) { if let Ok(mut m) = sent().lock() { m.insert(seq, Instant::now()); } }

/// JS calls this immediately on receipt of tick `seq`.
#[napi]
pub fn napi_latency_ack(seq: i64) {
    let seq = seq as u64;
    let start = sent().lock().ok().and_then(|mut m| m.remove(&seq));
    if let Some(t) = start { let _ = samples().force_push(t.elapsed().as_micros() as u64); }
}

/// Drain samples to JS for percentile computation (env-gated, like the flight dump).
#[napi]
pub fn napi_latency_drain(on_sample: ThreadsafeFunction<f64>) -> napi::Result<()> {
    if std::env::var("CORELIB_LOADGEN").unwrap_or_default() != "1" { return Ok(()); }
    while let Some(us) = samples().pop() { let _ = on_sample.call(Ok(us as f64), ThreadsafeFunctionCallMode::NonBlocking); }
    Ok(())
}
```
Wire `mark_sent(seq)` into `napi_load_generator`'s emit loop (Task 1.1). (SHAPE-DIVERGENCE STOP: the `Mutex<HashMap>` here is a TEST-ONLY latency-accounting structure, NOT on the production hot path — it must never be added to the real streaming pump. Note this in a comment.)

## Notes / risks

- **Threshold calibration:** treat the first Phase-3 soak run as calibration; if a standard runner can't drive enough load, escalate to a larger runner (in-process Rust generation makes this unlikely).
- **Sprawl control:** strictly linear phases; within a phase, probe→gate→commit per task; non-critical findings are backlogged, never fixed inline.
- **`heavy-probes.yml` is already on `main`** → the spec's "skeletal workflow to main first" is satisfied; only the JS-probe extension needs to reach `main` (controller checkpoint, Task 1.4).
